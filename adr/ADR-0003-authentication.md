# Аутентификация — JWT-токены



## Контекст и постановка задачи

Пользователь должен входить и выходить из системы (REQ-SEC-002), доступ к истории заказов разграничивается (каждый видит только свои заказы). Клиент — SPA (React).



Вопрос: хранить ли состояние входа на сервере (сессии) или передавать самодостаточный токен (JWT) клиенту?



## Драйверы решения

* Масштабируемость (разделение фронтенда и бэкенда).

* Простота реализации для SPA.

* Безопасность.



## Рассмотренные варианты

* Серверные сессии с cookie

* JWT в localStorage

* JWT в HttpOnly cookie



## Итог решения

Выбранный вариант: **«JWT в localStorage»**, потому что это стандартный подход для SPA-приложений (React + Spring Boot). Сервер не хранит состояние, что упрощает масштабирование.



### Последствия

* **Хорошо:** нет состояния на сервере.

* **Плохо:** риск XSS-кражи токена (требуется тщательная валидация ввода).



### Подтверждение

* Тест: запрос к `/api/orders` без токена возвращает 401 Unauthorized.



## Плюсы и минусы вариантов



### JWT в localStorage

* **Хорошо**, потому что просто для SPA.

* **Плохо**, потому что уязвим к XSS.



### Серверные сессии

* **Хорошо**, потому что безопаснее (cookie HttpOnly).

* **Плохо**, потому что требует хранения состояния.



\## Дополнительная информация

Связанные требования: REQ-SEC-002, REQ-INT-001.
