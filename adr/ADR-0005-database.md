# Выбор базы данных



## Контекст и постановка задачи

Данные о заказах, пользователях и меню должны храниться надежно. Требуется поддержка транзакций (ACID) для оформления заказов.



## Драйверы решения

* Целостность данных (ACID).

* Поддержка реляционных связей.

* Надежность.



## Рассмотренные варианты

* PostgreSQL (Реляционная)

* MongoDB (NoSQL)



## Итог решения

Выбранный вариант: **«PostgreSQL»**, потому что заказы и финансовые расчеты требуют строгой согласованности. PostgreSQL отлично справляется с реляционными связями (Пользователь -> Заказ -> Блюда).



### Последствия

* **Хорошо:** надежность, ACID-транзакции.

* **Плохо:** требует настройки схемы (миграции).



### Подтверждение

* Тест: при сбое транзакции данные не сохраняются частично.



## Плюсы и минусы вариантов



### PostgreSQL

* **Хорошо**, потому что ACID и реляционная модель.

* **Плохо**, потому что сложнее в настройке.



### MongoDB

* **Хорошо**, потому что гибкая схема.

* **Плохо**, потому что нет строгих транзакций.
