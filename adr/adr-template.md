# Выбор технологического стека для веб-приложения «Puff & Plate»

## Контекст и постановка задачи

Разрабатываемое веб-приложение «Puff & Plate» требует надежной клиент-серверной архитектуры для обработки заказов кейтеринга. Согласно спецификации требований (SRS), система должна обеспечивать высокий уровень безопасности (REQ-SEC-001) и производительности (время отклика < 1 сек, REQ-PERF-001). Также необходима гибкая бизнес-логика для расчета стоимости (включая порог бесплатной доставки, REQ-FUNC-007).

## Драйверы решения

* **Безопасность:** Необходимость встроенной защиты от атак и удобного механизма аутентификации (REQ-SEC-001).
* **Производительность:** Требуется время отклика при добавлении позиции в корзину не более 1 секунды (REQ-PERF-001).
* **Целостность данных:** Заказы и транзакции требуют строгой согласованности (ACID).
* **Гибкость бизнес-логики:** Легкость изменения правил расчета (например, изменение порога бесплатной доставки).

## Рассмотренные варианты

1. **Java (Spring Boot) + React + PostgreSQL.**
2. **Python (Django) + Vue.js + SQLite.**
3. **Node.js (Express) + Angular + MongoDB.**

## Итог решения

Выбранный вариант: **«Java (Spring Boot) + React + PostgreSQL»**, потому что он в наибольшей степени удовлетворяет драйверам «Безопасность» (Spring Security «из коробки») и «Целостность данных» (ACID-транзакции PostgreSQL). 

### Последствия

* **Хорошо:** Spring Boot позволяет легко вынести бизнес-логику (например, расчет бесплатной доставки) в отдельный класс. React обеспечивает быстрый SPA-интерфейс.
* **Плохо:** Java-приложения потребляют больше оперативной памяти при запуске.
* **Нейтрально:** Использование Docker нивелирует различия в операционных системах.

### Подтверждение

Соответствие решения подтверждается успешной компиляцией проекта (Maven), успешным прохождением тестов на расчет стоимости и отсутствием критических уязвимостей в зависимостях.

## Плюсы и минусы вариантов

### Вариант 1: Java (Spring Boot) + React + PostgreSQL
* **Хорошо**, потому что Spring Security решает вопросы аутентификации.
* **Хорошо**, потому что Hibernate (JPA) упрощает взаимодействие с БД.
* **Плохо**, потому что требует больше времени на первоначальную настройку.

### Вариант 2: Python (Django) + Vue.js + SQLite
* **Хорошо**, потому что быстрый старт разработки.
* **Плохо**, потому что SQLite не подходит для высоких нагрузок и параллельных транзакций.

### Вариант 3: Node.js (Express) + Angular + MongoDB
* **Хорошо**, потому что асинхронность Node.js позволяет обрабатывать много соединений.
* **Плохо**, потому что MongoDB (NoSQL) не гарантирует строгую целостность транзакций.

## Дополнительная информация

Решение принято на основе анализа документа SRS. Пересмотр возможен при изменении требований к нагрузке.
