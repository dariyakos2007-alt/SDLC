# Дополнительные спецификации прецедентов (Use Cases)
**Проект:** Веб-приложение «Puff & Plate»

## 1. Описание актёров

| Актёр | Описание (1–2 строки) |
| :--- | :--- |
| **Клиент** | Организатор мероприятия. Просматривает каталог, собирает заказ, применяет промокоды, оформляет доставку и просматривает историю заказов. Инициирует все основные прецеденты. |
| **Время** | Внешний «актёр». Инициирует событие наступления даты доставки, переводя заказ в статус «Доставлен» (SDD 2.2.11). |
| **База данных (PostgreSQL)** | Внешнее хранилище данных (ADR-0005). |

---

## 2. Спецификации прецедентов

### UC-01. «Просмотреть каталог»
* **Краткое описание:** Клиент просматривает список доступных сетов и блюд с ценами и ингредиентами.
* **Предусловия:** Приложение открыто.
* **Основной поток:**
  1. Клиент открывает экран «Конструктор заказа».
  2. Frontend отправляет запрос `GET /api/menu`.
  3. Backend возвращает список сетов и блюд из БД.
  4. React отображает карточки с информацией.
* **Альтернативный поток A1 (каталог пуст):** п.3 — возвращается пустой список; UI показывает «Каталог временно недоступен».
* **Постусловия:** Каталог отображён.

### UC-02. «Добавить позицию в корзину»
* **Краткое описание:** Клиент добавляет сет или блюдо в корзину.
* **Предусловия:** Выполнен UC-01 (каталог загружен).
* **Основной поток:**
  1. Клиент нажимает «Добавить» на карточке.
  2. Frontend обновляет состояние корзины.
  3. Система пересчитывает `total_items_price` (REQ-FUNC-003).
  4. Обновляется блок «Калькулятор».
* **Альтернативный поток A1 (позиция уже в корзине):** п.2 — количество увеличивается на 1.
* **Постусловия:** Позиция в корзине, стоимость пересчитана.

### UC-03. «Отфильтровать по аллергенам»
* **Краткое описание:** Клиент исключает блюда, содержащие выбранный аллерген (REQ-FUNC-006).
* **Предусловия:** Выполнен UC-01.
* **Основной поток:**
  1. Клиент выбирает аллерген в фильтре (например, «орехи»).
  2. Система исключает из отображения блюда с этим ингредиентом.
  3. Список обновляется.
* **Постусловия:** Каталог отфильтрован.

### UC-04. «Применить промокод»
* **Краткое описание:** Клиент вводит промокод для получения скидки (REQ-FUNC-007).
* **Предусловия:** В корзине есть позиции (выполнен UC-02).
* **Основной поток:**
  1. Клиент вводит код в поле и нажимает «Применить».
  2. Frontend отправляет `POST /api/cart/promo`.
  3. Backend проверяет код и пересчитывает итог.
  4. UI обновляет стоимость со скидкой.
* **Альтернативный поток A1 (неверный код):** п.3 — UI показывает «Промокод недействителен».
* **Постусловия:** Скидка применена или показано сообщение об ошибке.

### UC-05. «Оформить заказ»
* **Краткое описание:** Клиент вводит данные доставки и сохраняет заказ (REQ-FUNC-004, REQ-FUNC-005).
* **Предусловия:** В корзине есть позиции; клиент авторизован (выполнен UC-07).
* **Основной поток:**
  1. Клиент заполняет адрес, дату и время.
  2. Кнопка «Оформить» становится активной (REQ-FUNC-004).
  3. Клиент нажимает кнопку.
  4. Frontend отправляет `POST /api/orders` с JWT.
  5. Backend сохраняет заказ, присваивает номер и статус «Новый» (REQ-FUNC-005).
  6. UI показывает сообщение об успехе, корзина очищается.
* **Альтернативный поток A1 (не заполнены поля):** п.2 — кнопка неактивна.
* **Альтернативный поток A2 (401 Unauthorized):** п.4 — UI перенаправляет на страницу входа.
* **Постусловия:** Заказ сохранён в PostgreSQL; корзина очищена.

### UC-06. «Просмотреть историю заказов»
* **Краткое описание:** Клиент видит список своих прошлых заказов (REQ-FUNC-008).
* **Предусловия:** Клиент авторизован (выполнен UC-07).
* **Основной поток:**
  1. Клиент открывает личный кабинет.
  2. Frontend отправляет `GET /api/orders` с JWT.
  3. Backend возвращает только заказы текущего пользователя (REQ-SEC-002).
  4. UI отображает список (сначала новые).
* **Постусловия:** История отображена.

### UC-07. «Авторизоваться»
* **Краткое описание:** Клиент входит в систему и получает JWT (REQ-SEC-002, ADR-0003).
* **Предусловия:** Клиент зарегистрирован.
* **Основной поток:**
  1. Клиент вводит логин и пароль.
  2. Frontend отправляет `POST /api/auth/login`.
  3. Backend проверяет BCrypt-хеш (REQ-SEC-001) и возвращает JWT.
  4. Frontend сохраняет токен в `localStorage`.
* **Альтернативный поток A1 (неверные данные):** п.3 — 401; UI показывает ошибку.
* **Постусловия:** Токен сохранён, доступ к защищённым эндпоинтам открыт.
